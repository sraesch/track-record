# ADR 0005: Continuous integration with GitHub Actions

**Status:** accepted · **Date:** 2026-11-21

## Context

The repository is hosted on GitHub. So far it contains the database schema
with pgTAP tests ([ADR 0004](0004-database-schema.md)); the Rust backend and
the frontend follow. [ADR 0001](0001-technology-stack.md) left CI open.
There is nothing to deploy yet: no container image and no Helm chart.

## Decision

- **GitHub Actions**, one workflow: `.github/workflows/ci.yml`.
- **Triggers:** every pull request, and pushes to `develop` and `main`.
  Feature branches are checked through their pull request.
- **Jobs run the local commands.** The `database` job runs `db/test.sh`, the
  same script developers use. CI has no test logic of its own.
- **Only what exists.** A job is added together with the code it tests
  (`cargo test`, Vitest). No placeholder jobs.
- **No delivery yet.** Publishing images and the Helm chart is decided when
  the first deployable artifact exists.
- The workflow token is read-only (`contents: read`).

## Consequences

- A failing database test blocks a pull request once the `database` check is
  required in the branch protection of `develop` and `main`. Branch
  protection is a repository setting and not part of this ADR.
- The test image is built on every run (about a minute). Cache it if that
  becomes a problem.
- Actions are pinned to a major version. Pin to commit hashes if the
  workflow ever gets write permissions or secrets.
